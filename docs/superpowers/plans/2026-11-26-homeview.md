# HomeView Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename Kasa Home to HomeView, give its README HomePix's download buttons, and let the
desktop app update itself from GitHub releases the way HomePix does.

**Architecture:** The rename touches every name a person sees, plus the identifiers tied to the
product name: the app ID, file names, the keychain entry and the autostart entry. The updater lives
in the Electron main process (`apps/desktop/src/updates/`):

- a pure core: find the release, pick the file, download and check it;
- one installer per install kind;
- a small state machine, exposed to the page through the existing `ServerHooks` and local-only
  `/api/app/*` routes, and to the tray menu.

**Tech Stack:** TypeScript, Electron 45, Fastify, React, Vitest, electron-builder (NSIS, dmg, AppImage, deb).

**Spec:** `docs/superpowers/specs/2026-11-26-homeview-design.md`

## Global Constraints

- Product name `HomeView`. App ID `io.github.meirgarfinkel.homeview`. Linux program and package name `homeview`.
- Download files are exactly `HomeViewSetup.exe`, `HomeView.dmg`, `HomeView.deb` and `HomeView-x86_64.AppImage`.
- Repo `meirgarfinkel/homeview`. Releases API: `https://api.github.com/repos/meirgarfinkel/homeview/releases/latest`.
- Keep the internal names: the `@kasa/*` scope, `KASA_*` settings, the Kasa driver, `x-kasa-tunnel` and `kasa-tunnel`.
- Icon colours: circle `#373530`, camera `#9FDDA0`, record light `#FF7272`, roof and chimney `#FFFFFF`.
- Updates only on the computer running HomeView. `/api/app/*` stays local-only, as `appOnly` enforces.
- Nothing installs until Restart is pressed, or until the Linux password prompt is answered.
- Update checks: the first 60 s after start, then every 24 h. A background check that fails is only logged.
- Commits use author email `36854346+meirgarfinkel@users.noreply.github.com` and end with the two
  lines `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_014coFUwGw74CkTYA7BfwGKs`.
- Plain-words copy, sentence case, no em dashes (house style).

## Review Focus

1. **A release that has no file for this install kind** (say, a Mac file is missing). Expected: treated as "up to date", never an error loop. Test in Task 3.
2. **A download cut short, or with the wrong checksum.** Expected: the file is thrown away and the state is `error`, never `ready`. Test in Task 3.
3. **A Mac copy running from the dmg or from App Translocation.** Expected: a plain message to move it to Applications, with nothing touched. Test in Task 4.
4. **A second check or install while one is running.** Expected: no second download and no double install. Test in Task 5.
5. **A phone (a LAN request that isn't local) or a remote request** asking for the update status or install. Expected: 403. Test in Task 5.

### Task 3: Update core: find, pick and download

**Files:**

- Create: `apps/desktop/src/updates/release.ts`
- Test: `apps/desktop/test/updates/release.test.ts`

**Interfaces:**

- Produces:
  - `type InstallKind = 'windows' | 'mac' | 'appimage' | 'deb'`
  - `interface ReleaseAsset { name: string; browser_download_url: string; size: number; digest?: string }`
  - `interface Release { tag_name: string; assets: ReleaseAsset[] }`
  - `const UPDATE_FILES: Record<InstallKind, string>` maps to the four file names.
  - `howInstalled(env: { platform: NodeJS.Platform; packaged: boolean; execPath: string; appImage?: string }): InstallKind | undefined`
    - A deb install is an `execPath` under `/opt/HomeView/`.
    - An AppImage install has `appImage` set.
    - An unpackaged app gives `undefined`.
  - `versionOf(tag: string): number[]` turns `'v1.2.3'` into `[1,2,3]`, and anything that isn't a version into `[]`.
  - `isNewer(tag: string, current: string): boolean`
  - `fileFor(release: Release, kind: InstallKind): ReleaseAsset | undefined`
  - `latestRelease(url?: string, fetchImpl?: typeof fetch): Promise<Release>` sends `User-Agent: homeview` and `Accept: application/vnd.github+json`, with a 20 s timeout.
  - `download(asset: ReleaseAsset, dest: string, opts?: { signal?: AbortSignal; onProgress?(done: number, total: number): void }): Promise<void>` writes to `dest + '.part'`, checks the size and the `sha256:` digest, renames the file on success, and deletes the `.part` file and throws `Error('The download came through damaged. Please try again.')` on a mismatch.

- [ ] **Step 1: Write the failing tests:**
  - `howInstalled`: one case for each kind, plus unpackaged gives `undefined`.
  - `isNewer`:
    - `isNewer('v0.2.0','0.1.9')` is true;
    - `isNewer('v0.1.0','0.1.0')` is false;
    - `isNewer('v1.0.0-beta','0.1.0')` is false, because `versionOf` gives `[]`.
  - `fileFor`: a release with no `HomeView.dmg` gives `undefined` for `'mac'` (Review Focus 1).
  - `download`, against a local `http.createServer` serving 64 KiB:
    - with the right digest, `dest` exists and no `.part` file is left;
    - with the wrong digest, it rejects with the damaged message and neither file exists (Review Focus 2);
    - a server that ends early (sends 32 KiB with `size` 65536) rejects in the same way.

### Task 4: Installing each kind

**Files:**

- Create: `apps/desktop/src/updates/install.ts`
- Test: `apps/desktop/test/updates/install.test.ts`

**Interfaces:**

- Consumes: `InstallKind`.
- Produces:
  - `interface Runner { run(cmd: string, args: string[]): Promise<{ code: number; stdout: string; stderr: string }>; spawnDetached(cmd: string, args: string[]): void; which(cmd: string): string | undefined; openPath(p: string): void }`, with `defaultRunner` built on `node:child_process`.
  - `macBundle(execPath: string): string` gives the `.app` three levels up.
  - `replaceAppImage(newFile: string, appImage: string): void` does a chmod 0o755 then a rename. If the files are on different drives (EXDEV), it copies to `appImage + '.new'` and then renames.
  - `replaceMacApp(dmg: string, bundle: string, runner: Runner): Promise<void>`:
    - It throws `Error('Move HomeView into the Applications folder first, and open it from there.')` when the bundle path contains `/AppTranslocation/` or starts with `/Volumes/`, or doesn't end in `.app`.
    - Otherwise: `hdiutil attach -nobrowse -readonly -mountpoint <dir> <dmg>`, then `ditto <mount>/HomeView.app <bundle>.new`, then always `hdiutil detach -quiet`.
    - Then it renames the bundle to `.old` and `.new` to the bundle, putting `.old` back if that fails, and deletes `.old`.
  - `installDeb(file: string, runner: Runner): Promise<'installed' | 'opened'>`:
    - With no pkexec, it opens the file and returns `'opened'`.
    - Otherwise it runs `pkexec apt-get install -y <file>`.
    - Exit code 126 or 127 throws `Error('The update was cancelled.')`.
    - Any other non-zero code throws with the last line of stderr.
  - `startWindowsInstaller(file: string, runner: Runner): void` does `spawnDetached(file, ['/S', '--updated', '--force-run'])`.
  - `relaunch(kind: InstallKind, runner: Runner, paths: { execPath: string; appImage?: string }): void`:
    - Mac: `spawnDetached('sh', ['-c', 'sleep 1; exec open -n "$0"', bundle])`.
    - Otherwise: `spawnDetached('sh', ['-c', 'sleep 1; exec "$0"', appImage ?? execPath])`.

- [ ] **Step 1: Write the failing tests,** using temporary folders and a fake `Runner` that records calls:
  - `replaceAppImage` swaps the file content, and the new file is mode 0o755.
  - `replaceMacApp`:
    - with a fake runner whose `ditto` creates `<bundle>.new/marker`, afterwards `<bundle>/marker` exists and `.old` is gone;
    - with a bundle under `/Volumes/HomeView/HomeView.app`, it rejects with the Applications message and the runner was never called (Review Focus 3);
    - when `ditto` exits 1, the original bundle is untouched and `hdiutil detach` was still called.
  - `installDeb`:
    - no pkexec gives `'opened'`;
    - code 126 rejects with "The update was cancelled.".
  - `startWindowsInstaller` passes exactly `['/S', '--updated', '--force-run']`.
- [ ] **Step 2: Run them.** Run: `cd apps/desktop && mise exec -- pnpm exec vitest run test/updates/install.test.ts`. Expected: FAIL.
- [ ] **Step 3: Implement `install.ts`.**
- [ ] **Step 4: Run them again.** Expected: PASS.
- [ ] **Step 5: Commit:** "Updates: install each kind and restart".

  - `class Updater`:
    - Its constructor takes `opts: { kind: InstallKind | undefined; current: string; dir: string; runner: Runner; paths: { execPath: string; appImage?: string }; quit(): void; logger: Logger; latest?: () => Promise<Release>; download?: typeof download }`.

    - `check(opts?: { quiet?: boolean }): Promise<'up-to-date' | 'downloading' | 'ready' | 'not-installed'>`
    - `install(): Promise<void>`

    - `on('change', (s: UpdateStatus) => void)`.
  - The routes, both guarded by `appOnly`:
    - `GET /api/app/update` answers `UpdateStatus`.
    - `POST /api/app/update/install` answers 202, then calls `installUpdate()` once the reply closes.
    - `POST /api/app/update/check` answers `{ result }`.

  - calling `check()` twice at once calls `download` once (Review Focus 4);
  - `install()` with kind `appimage` calls `replaceAppImage`, then relaunch, then `quit` once;
